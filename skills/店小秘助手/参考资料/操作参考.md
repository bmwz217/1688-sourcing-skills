# 店小秘订单与导出操作

## 订单明细和商品图

旧 API 前缀为 `https://zhengxihuan.com/dianxiaomi`，参数以 [线上接口文档](https://zhengxihuan.com/dxm/doc) 为准。使用 Agent 的 `GET /v1/stores` 解析店铺。

- 查状态明细用 `GET /v1/stores/{key}/orders?state=状态&offset=0&limit=100`，按需要翻页，按 Amazon 订单号区分订单数量。状态包括 `approved` 待处理、`processed` 运单号申请（全部仓库）、`allocated_has` 待打单有货、`allocated_out` 待打单缺货、`allocated_exception` 待打单异常、`shipped` 发货成功、`shipped_fail` 发货失败、`refound` 已退款、`ignore` 已搁置。需要按指定仓库筛选时，以可核实的仓库资料为准。
- 查订单商品图用 `GET /v1/stores/{key}/orders/product-images?order_id=订单号`，图片按返回的 SKU 对应。商品品名或规格需要时，用在线 SKU 明细或带图订单表交叉核对。
- 同步用 `POST /v1/stores/{key}/orders/sync`，无需请求体，用 `GET /v1/stores/{key}/orders/sync-status` 查同步进度。同步全部店铺时，逐店调用并汇报各店结果。若用户要求同步后统计，在各店同步结果明确后再查询统计。

## Excel 和面单

| 操作 | 方法与路径 | 参数 |
| --- | --- | --- |
| 导出带图订单表 | `POST /v1/stores/{key}/orders/export` | JSON `{"order_ids":["订单号"],"size_unit":"cm"}`，按传入顺序，最多 50 单 |
| 下载单张面单 | `GET /v1/stores/{key}/orders/label` | 查询参数 `tracking_number` |
| 下载合并面单 | `POST /v1/stores/{key}/orders/labels/merge` | JSON `{"tracking_numbers":["运单号"]}`，按传入顺序合并，最多 20 个运单号 |

文件接口按单店铺调用。按表格顺序合并面单前，核对店铺、订单号和当前运单号。同订单的多个商品可能共用一个运单号，合并时保留该运单号首次出现的位置。检查 HTTP 成功状态和文件类型，Excel 应为 XLSX，面单应为 PDF，错误响应通常是 JSON。保存到用户指定路径，并核对已保存文件和订单的对应关系。

## 发货和移入待打单

在服务器本机通过已授权的运行方式调用，Agent 本机前缀为 `http://127.0.0.1:8090/agent`，旧接口本机前缀为 `http://127.0.0.1:8090`。若当前会话无法访问服务器本机，说明缺少哪一项连接条件。

1. 先核对用户授权的店铺、订单、SKU 和当前运单号。发货检查订单在「待打单 → 有货」，移入待打单检查订单在「运单号申请」且已取得运单号。
2. 发货用 Agent 的 `POST /v1/shipments`。请求头为 `Content-Type: application/json` 和 `Idempotency-Key`。每个发货意图使用唯一的请求键，重试沿用原键和原 JSON。JSON 字段为 `store_key`、`confirm: true`、`orders`，每笔订单包含 `order_id` 和 `tracking_number`，最多 20 笔。
3. 保存返回的 `operation_id`，用 `GET /v1/shipments/{operation_id}` 回查逐单状态。每笔 `confirmed` 或 `already_done` 才可报发货成功。若仍在核实，继续读取状态或通过 `state=shipped` 按原订单号和运单号核对，根据实际结果汇报。
4. 移入待打单用旧接口 `POST /v1/stores/{key}/orders/move-to-print`，JSON 传 `confirm: true` 和 `orders`。操作后回查指定订单是否进入 `allocated_has`。
