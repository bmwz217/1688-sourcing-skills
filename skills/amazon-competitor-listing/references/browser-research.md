# ego-browser 并发调研

## 任务空间

- 各独立任务使用独立 TaskSpace，首次按 `ego-browser skill` 的最新指南以本任务唯一标识命名，保存数字 ID。续做按该 ID 接续。用 `TaskSpace ID + 页面标签` 标识页面。只在能确认归属本任务的空间与页面操作。发现归属或控制权冲突时，暂停相关操作并按指南恢复。
- 在默认页面打开 Amazon.com，核实站点、配送邮编、观察日期和时区。已有合适邮编时沿用，用户没指定时用可核实的美国本土邮编，例如 `10001`。主智能体负责调整配送位置并复核，避免改账户已保存的地址。站点状态可跨任务共用，配送设置冲突时保留已核实样本并注明。
- 复用默认页，按需使用 `task.newPage()`，当前父 SKU 最多三个工作页。记录实际页面标签与 SKU、关键词、页码或 ASIN。Windows PowerShell 采用 UTF-8 `.mjs` 通过 `ego-browser nodejs -e` 导入，各执行者使用独立临时脚本路径。
- 页面用可见内容支持的选择器。可用 `page.goto()`、`page.snapshot()`、`waitForURL()`、`waitForSelector()` 或 `page.evaluate()`。查询后同时核对 Amazon URL 的 `k`、搜索框与结果区，并等待旧卡片换出。分页经观察到的按钮进入。若 Amazon 自动改词，区分提交与展示词并只给实际展示结果作证。

## 分派与恢复

1. 有可用子智能体时，主智能体分派关键词，通常一词一页，最多三个。发给各执行者 TaskSpace ID、已分配的页面标签、父 SKU、事实、词、配送邮编和需要的字段。执行者用 `taskSpace(ID)` 和 `task.page(label)` 领取，严格只使用分配页面，按 [研究指南](keyword-research.md) 回传联想、卡片、匹配程度和访问情况。
2. 主智能体跨词去重后分派详情核对，复用已完成搜索的页面。等上一位结束操作再重新分配，始终一页一人。子智能体回传取证记录，主智能体统一核复、写稿、校验、保存及管理配送与空间。在并发不足时，主智能体收回本任务页面并继续，可批量并行加载不同页面或逐页处理。
3. 加载异常先核对页面状态。需要登录、验证码或人工操作时，保留原标签和进度，由主智能体按指南交接。接续原空间并保留已核实证据；准确说明仍缺少的范围。
4. 正常结束后，主智能体按 ego-browser 指南在独立的最终轮次调用 `finish()` 一次。用户要求连续处理时复用任务页，逐父 SKU 保存独立检索与匹配记录。
