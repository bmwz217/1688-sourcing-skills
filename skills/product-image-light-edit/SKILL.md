# 基于真实原图制作亚马逊商品套图

为每个目标子SKU制作一张白底主图和有明确信息任务的附图。先确认实物与证据，再安排每张图要回答的问题、图型和编辑要求。用 ImageGen 逐张编辑，最后用原图和手机缩图验收。市场、语言、数量、输出规格及保存位置优先按用户要求。面向美国站时，附图用自然、简洁的美式英文。本技能用于有实物参考的商品图。仅下载素材和从零设计产品外观使用相应流程。

## 1. 核实当前SKU与证据

- 按用户指定范围处理父SKU与目标子SKU，不因尺寸小或其他原因默认排除变体。开工前找出至少一张能明确识别当前SKU的原图，核对颜色、尺寸或造型、出售件数、随附配件、适用参数及真实使用方式。
- 1688的“颜色”可能代表不同尺寸、姿势、造型、功能或套装。组图中只有明确归属当前SKU的画面才能作为证据。选图、编辑参考和验收均使用当前SKU自己的原图或从这些原图制作的当前稿件。不用其他SKU的图换色、拉伸、镜像或改姿势得到目标款。跨SKU共用参数须有明确出处，且证实适用于当前款。
- 比对商品属性、规格图、包装区及实物细节。记录数字的含义、单位和适用范围，区分产品尺寸与包装尺寸、净重与包装重、刻度印字与可宣称的量程或容量。图片中的外观和道具不足以证实材质、防水、耐热、承重、容量、食品接触安全、适配、续航或认证。
- 检查原图、产品自身标签、造型和图案有无疑似第三方品牌或受保护内容。发现明显疑似侵权标志或图案时标记并跳过相关SKU，依据不清时暂停受影响的SKU并请用户核实。SKU归属、出售件数或配件等关键事实无法确认时，记录待核实项并在必要时询问。其他有充分证据的图片或SKU继续推进。
- 优先用清晰、完整、遮挡少的本款实拍。去除工厂介绍、批发价格、起订量、店铺推荐等无关内容。重复照片择优。长详情图只取能说明当前SKU的部分。

## 2. 按买家问题制定套图计划

先列出这款商品最影响购买的疑问，从实拍和已核实资料中找答案，再选能把答案看明白的图型。没有A+时，按当前商品的购买优先级在套图中覆盖以下五方面，可在同一张图中回答紧密相关的问题。

- 让买家一眼认出商品和实际出售的内容。
- 说明主要功能及真实使用方式。
- 帮助买家判断尺寸、材质和适用场景。
- 用真实外观、表面和结构细节建立对商品品质的信任。
- 处理本款购买前最常见的疑虑，例如适配、安装、摆放、读数、随附内容或展示道具。

每张图以一个主要购买问题为主。按证据选功能展示、材质近景、基于实拍的体量对照、尺寸卡、示意、安装或使用步骤、场景等图型。优先保留有效的原图构图。确有必要时，可在模型编辑稿中辅助展示清晰、同款且有依据的实拍局部。不同图型和信息层次服务各图的用途，整套保持字体、色彩和视觉语气统一。相似场景、仅换标题或只换背景的画面通常无法解决新的购买问题。

在唯一的做图工作表中先登记实际计划和每图脚本。每张记录图序、主要买家问题、可支持的证据、图型或构图、拟用实拍参考、模型编辑目标、精准文案及必须保真的部位。涉及新场景时写清产品占比、接触位置和允许出现的道具。主图固定为 `01`，附图从 `02` 连续编号。

用户指定固定张数或上限时按其要求规划。仅有上限时，图数取决于能被真实证据支持、能够单独改善购买判断的问题。未指定时可用三张附图作为排期参考，按实际需要增减。素材不足时先完成有依据的图，并记录缺失证据和对张数的影响。以用户明确要求的数量或已经确定的实际计划为验收标准。无法达到用户硬性数量或已确认计划时报告具体缺口和实际张数，不以重复图或虚构信息补足。

### 证据不足时的表达

已核实参数才可用于数字标注，工作表保留出处。展示尺寸时用 `in / cm`，重量用 `oz / g` 或 `lb / kg`。核对单位、换算、测量端点和对象，避免把商品外形、包装数字或刻度最高印字误当成其他产品参数。

没有可靠数值时，可基于真实摆放场景或侧视原图做模型编辑，必要时加入标明非比例的辅助示意，说明买家应测量哪里、预留哪部分空间或查看哪种连接。示意明确参照面和目标部位，不加未经证实的数字或暗示等比例。未知实际尺寸时谨慎加入手持人物、常见尺寸物体等强比例参照，优先使用原照已有的自然参照。没有足够依据时改做其他有证据的题材或记录缺口。

## 3. 逐张使用 ImageGen 编辑

**每张主图和附图都以当前SKU实拍为参考，独立交给 ImageGen 编辑。成品以包含商品主体的模型编辑稿为基础。** 合格白底实拍可用作主图的参考，模型仅轻调曝光和留白。抠图、裁切放大、锐化、加字、转换格式、拼版后切分或只生成背景，都不能替代逐张对包含商品主体的画面做模型编辑。工作表记录实际采用的模型稿与参考映射。

- **按图给出编辑目标。** 指定已核对的同款实拍，写清买家问题、目标构图、允许调整的范围和必须保真的部位。场景图把商品和环境放进同一次摄影式编辑，统一视角、受光和接触阴影，让真实接触位置可见。
- **用足够清晰的参考做细节。** 选择关键部位在原照中可辨的实拍，避免把低清小裁片放大当作细节图。参考不足时，改用能证实结构的中景或其他有依据的用途主题。模型只能表现有实拍依据的纹理、轮廓、配件和结构。没有足够依据时记录缺口。
- **核对关键读数与标记。** 刻度、产品印字、标牌、孔位、连接点和颜色分区以原照为准。必要时可在模型编辑稿内保留经核实的清晰实拍小区域，或在信息层加已核实的精确标注。模型稿的印字或刻度与实拍不符时，用准确的实拍区域修复，或缩小编辑范围后重做，再按原照核对。
- **精确排版可独立完成。** 用设计工具或确定性脚本在本张的 ImageGen 编辑稿上排版英文、参数、尺寸线与辅助局部等。保持文字层可独立修订，主图保持无字。

### 商品保真与场景

- 保留同款的轮廓、比例、颜色、图案、涂装、纹理、开口、接缝、零件和配件。雕塑的表情、姿势、手持物也属于商品。实物被遮挡或截断时换用完整原图，缺失的背面、内部、装配或场景姿态不补画。
- 透明或反光商品优先选背景和曝光合适的原照作为参考，并控制编辑范围。核对透明件、开孔、折射、反光、薄杆和小部件。涉及蒙版局部修复时，在浅底和深底检查白边、透明边缘、刻度及细零件。
- 对照原图确认做旧、哑光等质感及颜色，避免校色或生成改掉真实涂装。核对场景中的商品比例和透视。桌面、地面、墙面或悬挂点须有合理接触，校验边缘、受光方向和阴影，避免商品悬浮或看起来像后贴上去。
- 展示道具不能暗示随货提供。必要时在附图标明道具仅示意。可移除不属于商品的店铺宣传，但保留商品自身真实印字、标签和标识。附图的文案简短、易读、准确，不遮挡要证明的商品细节。

### 实际发送云端的图片

本地原图、草稿或成品在作为云端生成、编辑或视觉核验的图片输入之前，使用 [scripts/compress_reference_images.py](scripts/compress_reference_images.py) 生成 Q90 JPG。已符合本脚本要求的同一图片可以复用。只在本地查看、裁切、排版或合成的文件不需要为此压缩或上传。

```powershell
uv run --no-project --with pillow --with pydantic python "技能目录/scripts/compress_reference_images.py" --output-dir "产品目录/草稿/子SKU/参考图压缩" "产品目录/SKU/原图.png" "产品目录/产品详情页/尺寸.jpg"
```

脚本默认保留分辨率，超大图片可用 `--max-side` 限制最长边。输出 JPG 会铺白，透明原图和用于合成或验收的蒙版仍保留为本地独立文件。每次只传本图所需的最少参考图，最多五张，工具限额更低时以工具为准。在当前子SKU的 `参考图输入清单.md` 记录目标图、实际发送的压缩 JPG 路径和字节数，并在工作表保留来源映射。

## 4. 逐图与整套验收

按实际图序打开每张成品，以原尺寸对照该图的原照和事实出处，再在同一顺序检查约360 px宽的整套缩图。

1. **原尺寸确认商品和事实。** 核对SKU、件数、颜色、形状、关键纹理和结构，检查蒙版、真实印字、实际连接、单位、数字、箭头端点、道具与场景含义。在实际交付尺寸核对要展示的纹理、印字和结构是否清楚并能在原照找到依据。放大后的涂抹、锐化光晕、噪点和生成纹理不能作为真实细节。
2. **缩图确认买家看得懂。** 主体和核心信息一眼可辨，必要文案与标注清楚，顺序自然，图与图之间信息互相补充。核对一致的视觉风格及因用途而异的版式。
3. **确认文件可交付。** 主图为纯白，只展示当前SKU实际出售的商品及随附件，商品完整，不新增文案、人物、道具、Logo或水印。保留商品自身真实标识。确认每张能追溯到该张包含商品主体的 ImageGen 编辑稿，编号连续、规格和格式符合要求、成品路径正确且没有混入草稿或其他SKU。

商品失真、细节模糊、关键事实错误、在目标大小难以读懂或文件不符合要求时返工，记录具体问题。模型改坏商品时，优先换用更清晰的原照重新编辑，或缩小编辑范围。可局部解决的问题在同一方法下最多返工两次。若证据不足，改用有依据的中景或主题，或保留已通过的进度并记录缺口。ImageGen 不可用时，保留已通过的进度并报告未完成图数。只复查改动图及其与整套的衔接。单纯审美差异且没有影响表达时不要求返工。

## 5. 批量调度、工作表与目录

批量任务按已有授权和环境以子SKU为单位独立分派，一个作图子智能体只处理一个子SKU。提供本技能及所需工具路径，明确父SKU、当前子SKU、草稿和输出目录。各SKU证据齐备即可开始，不等同父SKU的其他变体。并发按在用工具、子智能体和环境容量安排。主任务负责范围、分派、统一写工作表、验收与收尾，作图子智能体回传资料、逐图状态和路径。单款按实际任务处理。

主任务维护一份 `做图工作表.csv`，每张计划成品一行。字段可沿用已有表，在续跑时补齐缺项。

| 父SKU／子SKU | 筛查结论与计划张数 | 图序与主要买家问题 | 事实、原图路径与适用证据 | 图型、构图及编辑目标 | 文案、参数和关键保真项 | 实际云端参考与所用模型稿 | 状态、成品路径与缺口 |
|---|---|---|---|---|---|---|---|

批量进度统一为 `[已完成子SKU数/总子SKU数] 当前子SKU名称 - 进度状态`。状态可用“待处理、待检查、返工中、通过、缺素材、待核实、排除”。用户数量要求或已确定计划全部验收通过后，该SKU才计完成。按各SKU已确定的计划加总图片目标，注明待定项和实际已完成数量。

- 在既有选品目录中，原有 `SKU/`、`产品详情页/` 及其他来源保持只读。根目录使用唯一工作表。临时参考、草稿和核验文件放在 `草稿/<子SKU>/`，包括实际使用时的 `参考图压缩/` 与 `参考图输入清单.md`。必要的临时布局、辅助脚本可放在该草稿目录或任务已约定的工作目录，复用脚本可放在技能的 `scripts/` 或用户约定的工具目录。按同一范围清理本轮临时文件。
- `产品上架图/<子SKU>/` 仅放验收通过的该SKU成品。若任务指定其他输出目录，按用户位置保存。命名使用 `01_主图.jpg`、`02_附图_主题.jpg`，按实际计划连续编号。常规输出为 **1:1 JPG**，默认 **2000×2000 sRGB**。等比缩放，不拉伸商品或补造纹理。既有成品和记录保留，需新版目录时按任务安排。
- 核对交付完整性后清理本轮草稿和临时文件。递归删除前核实绝对路径在本任务范围内，且仅包含本轮生成内容。保留原素材、规定应留的记录、尚需续跑的过程文件及既有或不明归属的文件。最终报告各SKU实际张数、成品位置和仍待解决的缺口。
