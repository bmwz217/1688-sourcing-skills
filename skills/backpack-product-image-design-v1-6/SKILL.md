# 背包产品图设计v1-6

## 一、任务目标与工作原则

根据每个产品目录中的“SKU”和“产品详情页”原图，为每个目标子SKU（颜色或图案变体）制定并制作 **6–9张**亚马逊产品图。每色交付1张纯白底主图和5–8张美式英文附图，全部为1:1 JPG。按各颜色实际可用素材确定数量，每个颜色独立交付一套。

**核心流程：先筛查父款全部变体的疑似侵权迹象 → 选有信息差异的原图并按颜色定图数 → 批量压缩需使用的参考图并登记 → 用 ImageGen 逐张编辑、独立核验和保存。参考色全套通过后，调度其他颜色。**

有什么原图就做什么展示。优先保留原图中的产品、角度、结构、外观，主要调整清晰度、光线、背景、英文文案和排版；不要把已有原图重新描述成一个需要模型从头想象的产品。缺少某个角度时，换用现有的其他角度或细节主题。
如果产品图已经是设计好的，优先做产品图的局部修改，比如由中文排版的图改为英文版，仅需要修改文字，去掉水印，高清化图片等操作即可，有设计图而不是实拍图的时候尽量避免从头设计。
无设计好的图，也是尽量照搬图片，进行少量清晰化，轻微的光线瑕疵修复即可，尽量避免大幅度生成。
**不搜索、不套用网上其他产品的展示逻辑**。

图片数量由已确认的展示素材和方案决定。预估生成额度不作为减图或降低质量的依据。实际可用性以 ImageGen 工具响应为准；遇到限流或额度错误时保存进度并如实报告后暂停任务，并告知恢复的时间，设置定时恢复任务。

## 二、运行准备、并发调度与进度展示

**本地技能版本：** 主任务分派每个子智能体时提供本技能 `SKILL.md` 的实际绝对路径与版本 v1-6。子智能体首先读取该文件。图片压缩使用本技能目录下的 [scripts/compress_reference_images.py](scripts/compress_reference_images.py)，按实际安装位置解析绝对路径。

检查或设置codex 的 `max_concurrent_subagents` 子只能体并发上限为7，成功后提示用户重启codex，并发设置不生效不进行后续任何工作，ImageGen的并发数量不限。整个任务调度中，必须定期观察，让7个子智能体同时工作，保证出图效率。

- **主任务负责调度和交付。** 盘点父SKU和子SKU，分派任务，汇总唯一的图片工作表和总进度，协调文件冲突，核对成品文件并收尾。筛查原图、选择素材、设计、生成和视觉核验由子智能体负责。
- **每个子SKU独立分派。** 每个子智能体只负责1个子SKU，使用独立的草稿和输出目录，负责方案、生成和检查。参考色的子智能体先完成下述整个父款的素材筛查，生成范围仍限于自己的子SKU。参考色计划的全部图片验收通过后，同父SKU的其他颜色可以并行分派。每个子智能体汇报并获主任务接收后结束，环境支持时释放名额；新的子SKU使用新的子智能体。
- **按目标范围执行。** 款式超过3款或父SKU超过6个变体时直接分批。默认跳过明确标记的“小号”并记录，用户另有要求时按其要求执行。通过筛查且素材足够的目标颜色直接按方案制作。
- **父款筛查必须早于任何出图。** 有出图计划的父款由子智能体先浏览全部子SKU的颜色和图案、各款挂件、包体和内里可见标志，以及详情中能说明这些部件的原图。一个变体的迹象可能影响整个父款，不能只查参考色，也不能延后到其他颜色上机时再查。续跑时，凡缺少已完成全款筛查的记录，继续任何色的出图前先补查。筛查结果记在唯一的图片工作表。
- **疑似侵权处理（避免过度排除）。** 仅当原图中出现可明确识别的知名品牌标志或名称、受保护角色，或具有明确品牌识别度且与某知名品牌高度相似或相同的专属特征，才按明显侵权迹象处理。普通格纹、豹纹、动物纹、常见挂件/五金，以及模糊或无法识别的铭牌字样，不足以单独排除；无法确认具体品牌/IP或相似关系时，不要猜测或据此重命名，优先改用有依据且不展示该模糊标识的主题，只有确实无法安全判断或制作时才暂停核实。原图中的 Apple 手机、平板等道具本身不构成排除依据；生成图中不得出现 Apple 标志，可使用无品牌设备或调整取景。若产品本体出现明确知名品牌标志、受保护角色或高度相似的专属特征且授权不明，按用户已明确的授权处理方式执行：用户说无授权或不确定时，记录依据并跳过整款，按用户要求重命名为“<原SKU>- 涉嫌侵权”；用户明确要求恢复某父SKU时，按其具体指示继续，并避免在生成图中新增或突出无关品牌元素。
- **统一进度格式。** 主任务维护一份总进度，按 `[已完成子SKU数/总子SKU数] 当前子SKU名称 - 进度状态` 展示。分母为已纳入的全部目标子SKU，排除项不计入，待素材等仍待解决的子SKU保持待处理。某色实际计划数全部通过后才计为完成。图片总数按各色已确定的计划数加总，待定颜色单独标注，打包交付状态另记。

## 三、原图筛选、强制压缩与单表管理

### 1. 浏览筛选“清晰够用”的原图

先浏览“SKU”和“产品详情页”，了解有哪些颜色、角度、细节和参数。浏览用于筛选；真正用于生成的原图须打开看清楚。重复展示同一内容的图片，选最清晰、最完整、遮挡最少的一张即可，不逐张登记，也不反复检查未入选的重复图。

通常只需要找到：每个颜色的SKU图，以及现有的尺寸/参数图、背面或多角度图、内胆或部件细节图。没有的项目直接略过。厂家介绍、批发信息、起批量、装箱数量和其他产品推荐直接忽略，不纳入设计。

同时摘录原图明确提供的尺寸、重量、材质等参数，**仅在参考款草稿（`草稿/<参考款子SKU>/`）中记录一段“已确认参数”**并注明来源文件，供后续直接读取，不另建独立参数表。图片中能直接看懂的外观和结构不必逐项转写成文字清单。文本与图片冲突时，以产品图片为准；仍不清楚的参数不使用。

在能支撑至少6张有信息差异的图片、且至少1张附图可展示有来源的产品参数的颜色中，优先选详情图最完整的作为参考色。拟用参考色不满足时，在出图前改选同款合格的颜色，原拟用色按第四节的单色待素材规则处理。只有整款没有可用参考色时才暂停该款，在图片工作表记录具体缺口并向用户请求素材。其他颜色先确认各自SKU图，后续沿用已找到的角度和部件图。

### 2. 发送到云端前强制压缩参考图

任何本地图片在作为参考图附加到 ImageGen（imagegen）生成/编辑请求，或发送给云端进行视觉核验之前，**都必须先运行 `scripts/compress_reference_images.py` 转成 JPG（Pillow `quality=90`）**。禁止直接把原始 PNG、原始 JPG 或生成的 PNG 草稿作为云端输入；未经过压缩的图片发送到云端会消耗大量流量和token。

示例（输出目录按当前父SKU和子SKU调整；原图路径可一次列出多个）：

```powershell
uv run --no-project --with pillow --with pydantic python "F:/Codex/.codex/skills/backpack-product-image-design-v1-6/scripts/compress_reference_images.py" --output-dir "E:/产品目录/父SKU/草稿/子SKU/参考图压缩" "E:/产品目录/父SKU/SKU/颜色.png" "E:/产品目录/父SKU/产品详情页/尺寸.jpg"
```

示例路径须替换为实际路径。脚本输出 JSON，包含原图路径、压缩 JPG 路径和字节数，可据此填写工作表与输入清单。

执行后，只能把脚本输出的 `.jpg` 路径传给云端请求。脚本使用 Pillow 的 `quality=90`，保留原图分辨率，不覆盖原图；透明背景会铺白。相同内容的压缩文件可复用，不必为每次调用重复转换。即使输入本来是 JPG，也必须经过脚本统一转换。若 Pillow 不可用，先安装/切换到可用该库的 Python 环境再压缩，不得绕过步骤直接发送原图。

每个子SKU的 `草稿/<子SKU>/参考图输入清单.md` 必须逐次记录：目标图片、实际传入的压缩 JPG 路径和字节数。相同压缩图在不同请求中重复使用时，每次都单独记一条并计入累计输入量。每次生成只传入完成当前图片所需的最少参考图，**本技能每次最多传5张参考图；工具另有更低限制时遵守实际限制**，不为了凑数量混入无关角度或颜色。

**已有图片衔接：** 后续请求统一使用本节的 Q90 压缩输入。已有草稿或成品不得仅因历史输入曾采用 Q85 而重新生成；按本技能的产品事实、文案可读性及交付标准核验，通过即可复用。发现实际画质、产品或信息错误时仍须针对错误修复。

### 3. 全程只维护一张“图片工作表”

图片工作表同时记录父款筛查结果、每色实际计划张数、逐图主题、原图与压缩路径、状态、成品路径及返工原因。每张计划成品一行，保留原图路径，便于清理草稿后追溯。待素材颜色以子SKU为单位记缺口。已确认参数和必须逐次登记的 `参考图输入清单.md` 仍放各自草稿目录。多个子智能体并行时，各自只回传本SKU的行更新，由主任务统一合并。

**已有批次续接。** 有“9图工作表”时，在原表继续登记，沿用原文件即可。已通过的图和验收记录继续有效，原来已验收的整套9图照常保留。未完成的颜色可复用已有通过图，再按现有素材调整待做行与实际计划数。旧待生成行若不再属于方案，标记“不纳入计划”并记原因。需要衔接编号时优先给待生成图分配空位，确需调整已通过图片的编号时仅整理文件名并更新原路径映射，保留图像内容、来源和验收记录。参考图可以在多张图里复用，但各图必须提供不同的展示信息。

| 父SKU／子SKU／颜色 | 图序与主题 | 对应原始文件路径及压缩后JPG路径 | 简短编辑要求或文案方向 | 当前状态 | 成品路径／返工原因 |
|---|---|---|---|---|---|
| 示例：参考款 | 01 主图 | SKU/白色.jpg → 草稿/参考款/参考图压缩/白色_哈希_q90.jpg | 白底、清晰化，保留产品原貌 | 待生成 | |
| 示例：参考款 | 02 尺寸 | 产品详情页/尺寸.jpg → 草稿/参考款/参考图压缩/尺寸_哈希_q90.jpg | 沿用原图，转为美式英文及 in/cm 双单位标注 | 待生成 | |
| 示例：参考款 | 03 细节 | 产品详情页/肩带.jpg、拉链.jpg → 各自对应的压缩JPG绝对路径 | 细节小图排版，配英文标题与短标注 | 待生成 | |

## 四、按现有原图制定各色方案与文案

方案阶段按每个颜色的1688素材选定 **6–9张**。`01` 固定为白底主图，附图从 `02` 连续编号到实际计划数。每个主题应提供不同的商品信息。原图拍摄角度相同、正面和背面近似，或内胆与其他图展示高度相似时，优先保留清晰且能补充信息的图。换背景、改文案或换裁切本身不增加主题。已有素材适合时可以合并细节，缺少独特角度时选其他有证据的主题，无须凑到9张。若不足以支撑最低6张，或缺少有来源的产品参数，在图片工作表记录缺少的具体角度、部件、主题或参数，由主任务暂停该色并向用户请求素材。按第三节选定的参考色全套通过后，其他可制作颜色可按实际并发继续。

| 图片方向 | 优先使用的原图 | 编辑方法 |
|---|---|---|
| 主图（固定 01） | 对应颜色的SKU白底图 | 保持产品原貌，做清晰化、美化和纯白底整理，通常无需改变角度或结构 |
| 尺寸、重量图 | 原有尺寸或参数图 | 沿用原图表达或使用 W/D/H 参数卡，改善清晰度和排版，添加有来源的尺寸、重量及英文双单位文案 |
| 背面、多角度图 | 对应背面或多角度原图 | 直接编辑清晰化、统一背景和排版，保留原有角度及产品结构 |
| 场景图 | 清晰的整体产品图 | 用原图中的产品设计合适场景，保持产品外观和实际使用逻辑 |
| 属性、卖点图 | 整体图或相关细节图，加已确认参数 | 用真实属性和合理联想的用途提炼卖点，配美式英文文案 |
| 内胆、肩带、五金等细节图 | 对应部件的原始细节图 | 将已有细节交给 ImageGen 提取、组合成小图排版，按素材情况制作1–3张，不要求每种部件单独一张 |

- **尺寸图与参数卡止损规则：** 尺寸图以数值、单位和维度含义准确为准，不追求特定箭头或端点布局。可保留原图清楚的尺寸表达，也可用 `W/D/H` 参数卡；**箭头首稿不准确时，直接换成无箭头 `W/D/H` 参数卡，不反复尝试同类箭头提示词。** 高度是否包含提手按原图表达，不自行推断；重量未提供则不添加。
- **附图英文文案与双单位要求：**
  - 每色的5–8张附图均由 ImageGen（imagegen）按单张直接生成带完整排版的成品，使用**美式英文**。
  - 用清楚的英文标题和与主题有关的短标注组织信息。标题约3–10词、标注约4–6条且每条约3–15词，可作为排版参考。按表达需要增减，验收关注信息准确、易读、没有遮挡关键细节。词数、条数或纯审美偏好不单独触发重跑。
  - **至少1张附图含有来源的产品参数（未经实际测量不得称为实测）**（展示有来源的尺寸、材质或重量等产品参数）。
  - **北美单位为主，必须同时标北美+欧洲双单位：** 以北美常用的 `in`、`lb`、`oz` 为主，同时标注公制/欧洲单位（如 `in/cm`、`lb/kg`、`fl oz/L`）。
  - 可以根据真实属性联想日常、通勤、旅行、休闲或节日送礼用途；但容量、适配电脑尺寸、防水等级和承重等具体性能须有依据，不能靠场景联想推定或虚构数字。

## 五、背面、肩带、侧面和内胆参考规则

这些角度最容易生成错误，必须执行以下步骤：

1. 从已选原图中找到与目标款式相符的背面、肩带、侧面或内部图片，经压缩脚本转为 JPG 后实际传入 ImageGen，并在“图片工作表”写明路径。若缺少，再补找这一项即可。
2. 如果该角度只有其他颜色的原图，将该图和目标颜色SKU图（均压缩为JPG）一起交给 ImageGen 进行可靠换色；详情页中已有目标颜色的对应角度或部件图时，优先使用它。
3. 查看选定原图能否清楚说明本次展示内容。资料不足时不补画、不猜测，也不要求展示原图没有拍到的区域。
4. 背面或多角度原图清楚且能提供独立信息时，优先采用。与已有展示近似或缺少依据时，可选有信息差异的正面、材质、五金或其他细节主题。
5. **内胆展示规则：** 内胆优先沿用原图的开口、视角和局部拼图展示方式，不强行改变原图结构；**若制作整包内胆展示图，强制要求背包立放正面朝前、稍稍开口展示内部结构，以保证开口后包体不变形，不得虚构原图没有的内部隔层。**
6. 背面图对照该张原图，确认背面材质和颜色、背部口袋及拉链位置、肩带连接方式、提手和扣具没有明显改变。
7. 肩带图对照该张原图，确认所展示的肩带正反面、网面或泡棉、颜色、宽度、走向和调节结构没有明显改变。
8. 侧面图对照该张原图，确认包体厚度、侧袋、拉链、拼接和肩带位置没有明显改变，不新增原图没有的结构。
9. 双拉链在拉开时，展示拉链头要合理，不能直接展示在正面。

上述项目只核对本图实际展示的内容，不要求每张图展示全部部件，也不需要把这些项目展开成逐件填写的检查表。

## 六、直接编辑、逐张验收与返工止损

**每张图单独生成、单独验收。禁止先生成多图拼版再裁成多张成品。** 互不依赖的主题可以交错推进。当某图等结果或正在核验时，可准备下一张的参考图和提示词，并在工具支持且有空余并发时提交。必须依赖某个结果的图仍等该结果通过。工具只能同步执行时，提前备齐其他图素材，并按可用并发跨子SKU调度。并发请求中的每张图独立登记参考输入，继续遵守每次最多5张参考图与工具的实际限制。

每张图按同一个流程执行：

1. 从图片工作表取出本图对应的压缩后原图，交给 ImageGen（imagegen）编辑。说明本图主题、希望美化或调整的部分和美式英文文案。优先沿用原图中的产品和角度，保持实际颜色与结构。涉及多颜色时，说明哪张图提供结构、哪张图提供颜色。
2. 生成后实际打开成品，与指定原图直接比较，核对产品、文案及双单位参数。需发送云端进行视觉核验时，先把成品或草稿经 `compress_reference_images.py` 转为 JPG 并登记。
3. 符合标准的图独立保存并更新图片工作表。发现具体错误时，将本图记为“返工中”并加入返工队列，其他互不依赖的图片照常推进。

### 统一的通过标准（抓实物事实与可读性，忽略合理光影/排版差异）

生成要求和验收使用同一张原图、同一主题。判断重点只有：

- **产品是否仍是同一款：** 颜色、图案、主要轮廓正确；本图可见的口袋、拉链、肩带、提手、扣具及内部结构，没有会误导买家识别或理解功能的新增、缺失、错位或变形。
- **信息是否准确可读：** 美式英文、数字、双单位（`in/cm`、`lb/kg`）和功能说明正确，文案清楚且不遮挡关键展示内容。标题和标注按表达效果验收，不数词或数条作为通过条件。
- **是否满足成品要求：** 对应SKU正确，主附图用途正确，画面完整、1:1 JPG 比例和格式符合交付要求，无明显现实逻辑错误。

光线、阴影、细微纹理、摆放和排版等合理差异，只要不改变产品识别、功能理解和买家预期，即可通过。不以像素一致作为标准，不因“还能更美观”继续返工；原图未展示且本图也未展示的细节不判错。

**验收本质：这是供买家了解商品的上架图。实物事实不能编造，表达形式允许合理变化。满足这些要求就结束该图，不追加新的验收要求。**

### 发现错误与2次返工止损

在“图片工作表”原行用一句话记录“对应原图中的什么被改错”，针对该处编辑，不重新设计整套图。**同一问题返工2次后仍不准确，立即换用更清晰原图、原有局部细节或其他有依据的主题，不持续重试相似方法。** 仅重查修改后的图片，其他已通过图片继续保持通过状态。

没有具体可指认的产品或信息错误，不判返工。确实缺少依据时选其他真实主题。如因此无法形成6张相互区分的图，按第四节记录缺口并暂停该色。

## 七、参考款通过后可靠换色

**参考色方案中的全部图片逐张验收通过后，才开始其他颜色的生成。** 之后按实际资源开放同父SKU下多个颜色并行，每色由独立子智能体完成。

各颜色根据自己的原图决定6–9张的实际数量。优先复用参考色已通过且适用的主题、排版、文案或成品，结合目标颜色的压缩SKU图及已有的对应角度或部件图。颜色以目标SKU原图为准，结构以对应角度原图为准。有内里、肩带、背面等颜色或材质差异时，按实际图调整。缺少某角度依据时换成该颜色有依据的主题；参考色的计划数和图序不作为其他颜色的固定要求。每色的实际计划全部逐张验收后，才计为完成。

## 八、画面通用要求与代码限制

- **严禁代码作图/排版：** 所有产品图及文案均由 ImageGen（imagegen）直接生成或编辑。不得用代码绘制、拼接、修补、加字或排版成品图片；**代码仅允许用于文件整理、格式转换、尺寸检查以及运行参考图压缩脚本。**
- 主图为纯白背景，目标是接近 RGB 255,255,255，允许不影响白底效果的轻微偏差，不得使用灰度图；只展示实际产品，不加文案、人物、道具、额外 Logo 或水印。保留包体原有标签；用户明确要求去除的除外。
- 附图可以使用场景和道具，但不能遮挡关键展示内容或改变产品。默认使用18岁以上美国成人模特，不使用低龄儿童或亚洲面孔模特。
- 默认北美站，避免学校、校服、学习用品等容易引发 CPSC 误判的儿童场景及相关文案。用户明确指定欧洲站并需要此类场景时，按其要求调整。
- 不额外加入其他知名品牌 Logo、商标、包装或侵权元素。Apple 手机、平板等道具可作为无标志设备出现，但生成图中不得展示 Apple 标志；原图中出现 Apple 设备本身不构成排除父SKU的理由。不得出现明显违反现实使用逻辑的画面。

## 九、文件保存、非必要过程文件移入回收站与交付

原有“SKU”和“产品详情页”文件夹不得修改或删除，也不得在其同级目录直接散落保存图片。在每个产品原目录中，使用以下位置：

- `草稿/<子SKU>/`：该SKU的全部过程文件，包括测试图、失败图、返工图、`参考图压缩/` 和 `参考图输入清单.md`；参考款的“已确认参数”也放在自己的草稿中供其他颜色复用。
- `产品上架图/<颜色或子SKU>/`：只保存通过验收的计划成品，每色6–9张 1:1 JPG，编号从 `01` 连续到该色实际计划数。例：`01_主图.jpg`、`02_附图_尺寸.jpg`、`03_附图_细节.jpg`。颜色重名时用子SKU区分。
- 本次任务总目录维护唯一的图片工作表。图片可记为“待生成、待检查、返工中、通过、不纳入计划”。待素材及整款排除等情况写明具体原因。换主题在原行更新，并留一句原因。

子智能体完成当前子SKU后，向主任务提交本SKU的图片工作表更新和成品路径。每张图须有实际参考原图和检查结论。主任务接收并汇总后，结束该子智能体的工作，并在环境支持时释放名额。

**主任务收尾与非必要过程文件移入回收站：**
- 主任务按各子SKU实际计划数核对全部图片是否通过、文件是否存在、编号是否连续、是否为1:1 JPG以及成品目录是否无草稿，**交付前不例行增加一轮全图视觉复核**；确有具体疑点时，只另派新子智能体检查相关图片。
- **全部交付文件核对无误后，将本轮产生且确定不再用于返工、复用、追溯或交付的非必要过程文件移入系统回收站。**仅处理 `草稿/` 中能确认由本轮任务生成的具体文件；保留图片工作表、仍需复用的已确认参数、参考图输入清单及其他有追溯或复用价值的记录。来源不明或已有的文件一律保留。不得整体清空或永久删除 `草稿/` 文件夹，也不得触碰原始“SKU”、“产品详情页”、最终“产品上架图/”及其他交付文件。
- 使用系统支持的回收站操作，确认目标文件路径属于本次产品目录且文件确由本轮产生；**不得用永久删除代替移入回收站**。若当前环境无法安全移入回收站，或不能确认文件归属与必要性，停止清理并如实汇报。
- 移入回收站后，复核最终产品图和需保留的工作记录仍在原位，再汇报移入回收站的文件范围与数量，标记“收尾完成”。
