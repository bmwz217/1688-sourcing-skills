# 圣诞和家居装饰品自动化选品v1-2

## 0. 全局约束与运行机制

* **前置启动门禁（强制）**：开始任务前必须先向用户获取**内部 SKU 前缀**（如 `ZSD_1104`），**用户未提供 SKU 前缀时严禁开始任务**。同时确认目标 1688 店铺、商品分类（相近商品归入同一类，合并后最多 10 类）及本地保存位置。范围限定为圣诞和家居装饰品。
* **网页操作**。1688 店铺浏览、价格筛选、分页与链接采集，以及 Amazon 竞品调研，统一使用 [ego-browser 技能](<C:/Program Files/Citro Labs/ego lite/Application/0.6.3.17/ego-skills/ego-browser/SKILL.md>)。首次操作前运行 `ego-browser skill` 并遵循当前版本的指南，复用同一任务空间和对应标签页。禁止使用内置浏览器、Google Chrome 或 Microsoft Edge 执行这些网页操作。第 2 节的旧下载器继续使用自己的 Edge 会话。
* **利润表路径**：默认使用技能文件夹中的 `选品表模板.xlsx`（复制生成本次输出表，保留原始模板不被污染）。利润表必须保存到本次选品根目录，即与 `ZSD_1116_001` 等商品 SKU 文件夹同级；不要放入 `outputs` 子目录或单个 SKU 文件夹。每次完成选品时，还必须在同一根目录交付 `未入选商品及理由.csv`，具体要求见第 5.3 节。
* **工作过程文件管理**：下载日志、链接清单、筛选结果、视觉核对记录、Amazon调研、中间脚本、预览图及其他临时文件一律放入本次选品根目录下的“工作过程”。最终表格和分类复核通过后，使用本技能清理脚本删除整个“工作过程”目录。
* **无待核状态与目录清理**：全流程不设置“待核/待确认”状态。任何影响入选判断的资料、图片、重量、尺寸或商品属性无法确认，核对现有原图和资料后仍不明确的，一律判为“淘汰”，不进入利润表。只保留最终通过并写入利润表的产品目录；淘汰和重复淘汰目录每累计确认50款先预览并清理，任务结束时清理不足50款的剩余淘汰目录。严禁直接用命令删除 SKU 目录；必须用 scripts/cleanup_selection_folders.py 和“工作过程/全店最终状态.csv”完整状态清单，清理后复核目录仅剩通过产品。
* **单点写入与主键关联**：同一执行流负责链接采集和下载；链接清单和利润表各由单一入口写入。全流程统一按 `1688商品编号` 匹配商品资料、图片、成本和表格行。
* **进度监控**：定期记录当前进度、下载数、通过数、重复数、淘汰数和各环节用时。保存进度、阶段汇报或入选率偏低时，保持流程继续执行不中断。
* **未入选每10条报告**。每新增10条已定案的未入选商品（含重复淘汰），立即向用户报告截至当前的累计原因统计。使用两列表格“未入选原因｜数量”，按数量从多到少排列，末行写未入选合计。原因用通俗中文说明，例如“原图没有可用重量”“起批量超过3件”“明确已售达到2,000”。每款按一项主要淘汰原因计数，合计必须等于累计未入选数；其他问题保存在逐款记录。报告后继续选品，恢复任务时沿用已报告进度。
* **已售数量为可选字段**。初筛、复核和入表统一按第 3 节执行。缺少已售数量的商品直接通过销量筛选。
* **定制款先跳过**。第一次确认商品以定制方式出售时，记录内部 SKU、商品名和 1688 链接，标为“定制款暂略”，立即继续下一款。定制款跳过后续下载、筛选、Amazon 调研和利润表，选品完成后另列全部定制款链接。以购买区实际下单方式为准，如显示“立即定制”，或仅提供轻定制、重定制、打样、拿样等方式。可直接购买的商品即使提供加字、换包装等可选服务，也按现货筛选。
* **风控与中断恢复**：遇到登录、授权或验证码时，暂停受影响的步骤，**保留原浏览器标签页**，记录当前 `1688商品编号` 或 Amazon 搜索关键词，以及当前进度。ego-browser 阶段同时记录任务空间 ID 和标签页；用户需要操作时，在原任务空间交还控制权，完成后接回同一空间继续。旧下载器阶段按下载器提示在原 Edge 标签页完成验证。无需人工介入的临时中断按用户指定间隔刷新原标签页（未指定时默认每 5 分钟 1 次，最多 4 次）；仍未恢复时报告具体问题。截图仅用于记录筛选过程，商品核对必须使用本地下载的原图。

## 1. 网页粗筛与链接采集（`$ego-browser`）

1. **网页价格粗筛**：使用 `$ego-browser` 打开目标 1688 店铺并选择指定分类，**直接在网页端设置价格筛选区间（默认 `¥17～¥65`）**，从第 1 页遍历至最后一页记录全部商品链接。
   * *说明*：1688 网页价格筛选为“宽进”机制（任一引流 SKU 在区间内即会展示整条链接），此步仅作前端粗筛，具体 SKU 真实采购价在下载后本地核验。
2. **去重与对账**：记录店铺显示的商品数和实际采集到的链接数。同一 1688 商品只保留第一次出现的链接，记录去重后商品数并与店铺显示数量核对，存在差异时记录差额。
3. **保留价格初筛依据**：按本次指定分类采集未设置价格时的分页商品清单，记录商品编号、名称、分类、原页位置、链接和列表展示价。与同一范围的价格筛选结果按 1688 商品编号去重对账，逐款记录未出现在价格筛选结果中的商品。仅在有列表价证据时写明低于下限或高于上限。全量分页尚未采齐时，记录缺口并继续采集。
4. **保存链接清单**：按原顺序将链接清单保存到 `工作过程` 文件夹，每条记录包含：`分类`、`页码`、`页内位置`、`1688商品编号`、`链接`、`内部 SKU`、`保存目录`。

## 2. 批量下载原图与资料（`$1688-image-downloader-v1.1`）

1. **批量拉取原图与资料**：使用 `$1688-image-downloader-v1.1` 的旧下载器按清单顺序下载，在指定目录下为每个商品建立独立的 SKU 文件夹，保存 `商品信息.json`、`产品文本介绍.txt`、`sku` 原图和 `产品详情页` 原图（单商品图片并发下载，失败由下载器自动重试）。下载器继续连接原有本地调试端口 `127.0.0.1:9222`，端口未就绪时由下载器启动 Microsoft Edge。
2. **复用与校验**：
   * 同一商品本地已有有效原图且购买信息仍有效时，可直接使用；重新下载时先入临时文件夹，按 `1688商品编号` 核对无误后再替换。
   * 核对 `商品信息.json` 中的 `source_url` 与清单中的 `1688商品编号` 一致。逐个记录文件夹路径、JSON 路径、两类图片的下载成功数、失败数和失败原因。
   * **单规格原图**。用购买区实际可下单的规格识别单 SKU，无颜色选项也可确认规格、采购价和库存。若页面没有独立规格图，核对商品主图或详情原图是否清楚对应唯一在售规格，可确认时作为该款原图保存并注明来源。
3. **在线阶段收口**：整批下载并登记结果后，在线采集环节结束，全面转入本地筛选。下载失败且缺少核心判断依据的，记录失败原因并判为 `淘汰`，不进入利润表；中断后从未完成的商品继续下载，直至能判定通过或淘汰。

## 3. 本地双层漏斗精筛（先 JSON 后识图）

按清单顺序逐个遍历本地 SKU 文件夹，严格执行“第一层 JSON 硬过滤 $\rightarrow$ 第二层图片精准识别”的两步流水线，避免在明显不合格商品上浪费识图算力。

### 第一层：JSON 与文本硬过滤（零视觉识图）

先读取文件夹内的 `商品信息.json` 和 `产品文本介绍.txt`，核对标题、已售数量（`sold_text`）、起批量（`minimum_order_quantity`）、起批单位和原文、国内运费（`domestic_shipping`），以及各款采购价和库存（`skus`）。**仅把 `库存 > 0` 的款式计为在售款**。
按颜色和尺寸组合核对。规格行显示“库存不足”、售罄或无法下单时，排除该款，不用它计款数或最高采购价；未显示库存的款继续核对购买原文或同页规格数据。

触发以下任一条件，**直接判定为 `淘汰` 并记录原因，跳过该文件夹所有图片，立即进入下一个文件夹**：

1. **价格越界**：任一在售款的采购价超过上限（默认 `¥65`），或按卖家实际售卖方式找不到符合 `¥17～¥65` 区间（国内运费另算）的在售款。
2. **规格和起批量上限**。在售款超过 12 个或起批量超过 3 时淘汰。
3. **已售数量上限**。按 1688 商品详情购买区中标明“已售”的数值核对。已售达到 2,000 时淘汰（含“已售2,000+”）。预估销量、全网销量、想买人数和加购人数均不得用来补填。缺少已售数量时，按低于 2,000 处理，直接通过销量筛选。已售栏留空。
4. **文本带电特征**。标题、属性或产品文本介绍中明确使用电池、插头、USB，或明确描述商品本体发光。

### 第二层：图片识别与规格合成（仅看第一层合格文件夹）

通过第一层的商品，按在售款匹配 `sku` 原图，结合 `产品详情页` 原图、商品说明和列表主图进行视觉识别与信息合成。

1. **Python 批量清理详情页废图与看图规范**：
   * 每个商品的 `产品详情页` 文件夹中常包含统一的厂家宣传图与无关推荐图。先抽查前 10 个合格商品的详情图，记录这些无关图的**精确字节数（及 MD5 哈希值防止误删）**，编写并运行 Python 脚本在所有合格文件夹中批量删除匹配该字节数与哈希值的无关图片，然后再进行视觉识别。
   * 识图时必须视觉区分商品本体与拍摄道具，款式细节以 `sku` 原图为准。
2. **视觉淘汰与信息确认**：
   * **隐性带电淘汰**：原图显示商品本体发光，直接按带电 `淘汰`；背景出现灯串时，必须核对灯串是否属于售卖商品本体（属于则 `淘汰`）。
   * **合规与图文一致性**：商品有明确侵权风险、图文严重不符，或打包后实际总重 `> 1 公斤`，直接 `淘汰` 并记录依据。
   * **不明确即淘汰**：遇到字段缺失、在售名单不明、资料冲突，或件数、规格、包装重量、侵权情况无法确认且影响入选结果时，先核对本地原图、说明和同商品历史有效记录；仍无法确认则判为 `淘汰`，不进入利润表，并纳入淘汰目录清理。
3. **套装与单品成本核算**：
   * 按卖家实际售卖的款式、件数和价格核算，**严禁自行拼套或拆套试算**。
   * 套装件数以对应在售款原图上的包装或卖家套装标识为准。标识清楚时，即使逐件数出的数量不同，也采用标识数量。
   * **有现成在售套装时**：只核算套装，按整套采购价和包装后重量判断（但单品价格仍须符合最高价限制）。
   * **无现成套装时**：合格单品分别作为款式，以**合格款中的最高采购价 + 国内运费**计算商品成本。
   * **在售款同款不同大小时淘汰**：同一个链接的产品上架后会归为同一变体并使用统一售价，若 `库存 > 0` 的在售款为外观相同但尺寸不同的规格（如“大号 / 中号 / 小号”），直接 `淘汰`。
   * **国内运费规则**：保留运费原文和金额。凡带“起”字的运费直接当作准确运费计算（例如 `8元起` 即按 `8元` 计入成本）。
4. **重量与包装核算**：
   * **屏蔽网页虚假克重**：**网页包装表、参数栏及 JSON 属性中的整百克数直接忽略**（如 `100克`、`400克`、`500克`），既不用于估重，也不作为重量冲突依据，视为虚假数据。
   * **图片属性为准**：重量、尺寸及其他商品本体属性，以本地对应在售款的 `sku` 原图和产品详情原图为准。图片信息与 JSON、文本介绍或网页文字冲突时，采用图片信息；优先匹配具体在售款的图片。图片缺失、无法辨认或图片间冲突影响结论时，核对后仍无法确认则判为 `淘汰`，不以文字数据替代图片结论，也不进入利润表。按图片重量记录单位，并区分商品净重和含包装毛重；包装增重规则见下条。
   * **包装增重与上限**：包装后实际总重最多 `1 公斤（1000g / 1kg）`，尺寸或体积换算不能代替实际重量。包装方式不明时按袋装 `+20克` 估算；明确为盒装时 `+50～100克` 估算；原图重量已含包装时不重复累加。分别记录卖家标注、实际称重、估算值和未确认重量。
   * 原图找不到可用重量依据时淘汰。包装增重估算只适用于已有可确认商品重量的款。
5. **输出本地筛选结论**：合成 JSON 商业数据与识图物理数据，为每个商品标记 `通过1688筛选`、`淘汰` 或 `重复淘汰`，并注明详细原因。只有关键资料完整、图片依据足以确认且满足全部筛选条件的商品才能标记通过；不明确的商品一律淘汰。

## 4. Amazon 快速调研与利润计算

1. **Amazon 竞品调研**：
   * 使用 `$ego-browser` 打开 Amazon.com 并搜索竞品。每款产品都要做 1 次 Amazon 调研，**最多搜索 3 次**（优先使用与商品最接近的核心关键词），同款产品可归为同一次调研。
   * **样本筛选**：优先选取评论数 `5～200` 的可比商品；样本不足时扩大到 `200～1,000`。
   * **快速价格统计**：搜索找到近似款后，按单件折算汇总可比样本的市场价格区间（用于填入 `AC列 市场价`，如 `16-20`）。找不到可靠样本时记录缺项（**市场价高低不作为淘汰条件**）。
2. **目标售价反推测算**：
   * 结合 `S列 商品成本(元)` 和 `T列 重量(kg)`，套用利润表既有公式，反推使 `AB列 利润率` 落在 **`75%～85%`** 目标区间的建议 **`M列 定价美金`**。

## 5. 选品利润表黄色列映射与程序校验写入

### 5.1 表格列操作规范（严格对照 `选品表模板.xlsx`）

* **黄色指定写入列（仅写入以下 12 个黄色列，必须逐列填全）**：

| 列号与列名 | 填写内容与格式要求 |
| :--- | :--- |
| **`D列 图片`** | 嵌入 1 张主推合格在售款对应的本地 `sku` 原图 |
| **`E列 采购链接`** | 1688 完整商品网址 |
| **`F列 厂家`** | 从用户最初提供的 1688 店铺网址读取店铺名称；同一批商品来自该店铺时复用该名称，不逐款从 JSON 中另取厂家 |
| **`G列 产品分类`** | 归类后的类目名称（如 `圣诞挂件`） |
| **`H列 产品名称`** | 基于 1688 原标题清洗后的规范中文商品名称（去除促销、现货、平台等无关词，保留核心品类与特征） |
| **`I列 SKU数量`** | `库存 > 0` 的合格在售款式总数量（纯数字） |
| **`J列 SKU`** | 按用户提供的 SKU 前缀 + 日期 + 序号生成的内部唯一编码（如 `ZSD_1104_001`） |
| **`M列 定价美金`** | 反推使 `AB列 利润率` 达到 `75%～85%` 目标区间的建议美元售价（纯数字） |
| **`S列 商品成本`** | `最高采购价 + 国内运费`（纯数字，单位：人民币元） |
| **`T列 重量`** | **打包后的含包装总重量，单位必须换算为 `公斤 (kg)`**（纯数字，必须 `≤ 1`，例如 `150克` 必须填 `0.15`，**严禁直接填克数**） |
| **`AC列 市场价`** | Amazon 调研可比样本的美元市场价区间（如 `16-20`，无可靠样本写缺项说明） |
| **`AD列 选品备注`** | 写入估重依据、Amazon 样本口径或已确认的商品说明，**严格限制在 100 字以内** |

* **非黄色列处理原则（共 18 列，严禁篡改结构与公式）**：
  * **固定默认值列（新增行直接向下复制第 2 行模板值）**：A列序号递增、B列国家美国、C列在售状态待上架、K列币种汇率6.67、L列兑美元汇率1、N列高于主站为主站、O列亚马逊配送费3.7、U列每公斤运费95、V列处理费19、X列税率0.85。
  * **自动公式列（严禁写入静态数值覆盖，新增行必须向下填充第 2 行原公式）**：`P列 订单收入`（第 2 行 `=M2+O2`）、`Q列 税后售价`（`=P2*X2`）、`R列 税后售价(人民币)`（`=Q2*K2`）、`W列 出境运费`（`=T2*U2+V2`）、`Y列 总成本`（`=W2+S2`）、`Z列 退货率5%和重量偏差损失`（`=R2*0.05`）、`AA列 利润`（`=R2-Y2-Z2`）、`AB列 利润率`（`=AA2/Y2`）。

### 5.2 分批落盘与写前/写后校验

1. **每10款滚动写入并保存**：每累计完成10款通过筛选并完成Amazon调研的商品，就立即将这10款追加到本次利润表并保存到选品根目录（与商品SKU文件夹同级）；全程使用同一张利润表，按内部SKU更新或去重，不另存阶段版本。最后不足10款的余数也要写入并保存。
2. **写前程序强制校验**（未通过检查的行记录原因并跳过，不阻塞其他合格行写入）：
   * **必填列与格式**：核对全部 12 个黄色列无缺失或格式错误，确认 `AD列 选品备注 ≤ 100` 字。
   * **重量与单位合规**：核对重量来源、是否含包装及确认状态；确认 `T列 重量` 已正确换算为 `公斤 (kg)` 且 `≤ 1`（防止误填克数导致 `W列 出境运费` 算错），估重已注明依据，包装重量仅累加一次。
   * **图片可用**：核对 `D列 图片` 对应的本地原图可正常打开、与主推在售款一致，且正确嵌入对应单元格位置内。
   * **公式完整**：保留所有白色公式列原公式，核对向下填充后的行列引用无错位，确认 `AB列 利润率` 计算结果落在 `75%～85%` 目标区间。
3. **写后复核与全局汇总**：
   * 保存后重新打开利润表，核对新增和更新记录、商品总数、图片位置、公式及报错状态（确认无 `#DIV/0!`、`#REF!`、`#VALUE!` 等报错），通过后标为 `已写入`。若保存失败，先核对表格和清单状态再重试。
* 最终汇总输出：**清单商品总数、下载成功数、通过数、淘汰数、暂略定制款数**。全部选品及最终复核完成后，按“未入选原因｜数量”两列表格再报告一次最终累计原因和合计，最后不足10条也计入。定制暂略款另报数量，并列出完整链接，按 1688 商品编号去重；如保存链接清单，放在选品根目录，随利润表一起交付。
4. **淘汰目录分批清理**：先把全店每个 SKU 的最终状态合并为唯一一行，状态只能是“通过1688筛选”“淘汰”“重复淘汰”或“定制款暂略”，保存到“工作过程/全店最终状态.csv”。已采集的定制款资料放在工作过程目录，定制款单独统计。每累计确认50个淘汰或重复淘汰商品，先运行清理脚本预览数量，再加 --execute 执行；脚本默认每批50个。全店处理结束时，即使不足50个，也必须清理完整状态清单中的所有淘汰目录。校验后记录删除日志，并确认目录中不再残留任何未入选产品；可中断后使用同一完整状态清单续查，只有通过目录必须仍存在。
   * 完成最终利润表、未入选理由表及全店状态复核后，运行同一脚本的 --delete-work-process 模式预览，再加 --execute 清理工作过程目录。不得在交付前删除工作过程文件。

### 5.3 未入选商品及理由表（必交）

* 保存为选品根目录下的 `未入选商品及理由.csv`，使用带 BOM 的 UTF-8 编码。固定列为：商品编号、商品名称、店铺分类、分类页码、页内位置、1688链接、列表展示价（元）、内部SKU、选品结果、未入选原因。尚未分配内部 SKU 的行留空。
* 覆盖本次范围内所有未入选商品，包括未通过网页价格初筛、详筛淘汰、确认重复淘汰，以及最终复核剔除的商品。每个 1688 商品编号最多一行，重复出现的同一商品只记一次，最终通过的商品从此表排除。定制暂略款按原流程单独汇总。
* 写明可核对的具体理由，例如“列表展示价 8.80 元，未出现在 17–65 元筛选结果中”或“在售规格 20 个，超过 12 个上限”。每款以一个主要原因计入最终统计，其他已确认问题可写在同一行。未入选为零时照常交付列头。
* 在清理工作过程前，用全量商品清单核对：去重总数 = 利润表入选数 + 未入选理由表行数 + 定制暂略数。逐行确认链接、商品编号与理由齐全，最终原因统计与理由表行数一致。复核剔除商品后同步更新该表，再与利润表一起交付。

## 6. 选品完成后的目录与利润表逐款复核

最终利润表写入完成后、清理“工作过程”目录前，必须对利润表中的每款商品逐一复核，不得只抽样。销量按第 3 节核对。入选必需的信息或图片依据无法确认时，从利润表剔除该商品，在全店状态清单中标为“淘汰”，并按清理流程删除产品目录。随后重新复核利润表和目录。

1. **分批并行检查**：使用多个子智能体将利润表数据行按互不重叠的行范围分批检查；每个子智能体负责一段连续行，并报告覆盖的起止行和完成数量。按商品数量调整批次数，确保所有表格行都被覆盖、没有重叠或遗漏。若无法使用子智能体，按同样的完整覆盖要求自行分批完成。
2. **逐款识别产品**：对每一行的内部 SKU 打开对应产品目录，读取 `商品信息.json` 和 `产品文本介绍.txt`，并至少查看该目录中一张 SKU 主图。结合图片、SKU 名称和文字资料，核实产品类型、款式、节日属性、表格分类与产品名称是否相符；若识别需要尺寸或重量依据，也要查看相应详情图。重量、尺寸和其他产品属性以图片为准；文字、JSON 与图片冲突时不以文字覆盖图片。图片缺失、模糊或无法确认时，该商品不符合入表条件，按上述规则从表格剔除并清理目录。
3. **逐行核对表格数据**：检查表格 SKU 与目录名一致；采购链接中的商品编号与 `商品信息.json` 的 `source_url` 一致；`I列 SKU数量` 等于库存大于0的在售 SKU 数；`S列 商品成本` 等于最高在售采购价加国内运费；`T列 重量` 与图片可确认的含包装重量相符且单位为 kg；`D列 图片` 非空并对应目录中的产品；`F列 厂家` 为初始店铺名称。逐款检查 `G列 产品分类`、`H列 产品名称`、SKU 款式与主图是否错配。目录和利润表必须一一对应；信息不足或无法确认的产品不得保留在利润表和产品目录。
4. **全表程序核对**：检查 SKU 和采购链接重复、必填列空缺、固定汇率/费用值是否符合本次设定；逐行核对 `P/Q/R/W/Y/Z/AA/AB` 公式引用是否与所在行一致，并独立复算结果。检查利润率目标范围、公式错误值（如 `#REF!`、`#DIV/0!`、`#VALUE!`），以及利润表行是否都能对应到产品目录。
5. **汇总与清理**：每个子智能体只报告疑点或错误，并注明利润表行号、内部 SKU、列名、表格现值、预期值及证据文件名/图片；主智能体合并去重、复核异常，并报告已检查行数、异常数和未覆盖项。所有核对清单、临时数据和审查记录均放入“工作过程”；汇总完成后，按本技能的目录清理流程删除“工作过程”。
